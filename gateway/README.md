# Strata page-gate prototype

This is a development prototype, not a deployment guide. Do not expose it or point a production tunnel at it yet. It has not had an independent security review, and the complete browser login path through OAuth2 Proxy is not yet verified.

The intended flow puts a standard OIDC proxy in front of this local-only gateway. The gateway introspects the proxy's access token for every page request and rejects inactive tokens, tokens from another OIDC client, expired tokens, and revoked invitations. Strata still receives the API key the user enters in its existing interface. The gateway does not store or inject a Strata primary or secondary key.

For compatibility, `/v1/` requests carrying a bearer or `x-api-key` credential bypass browser login and pass that credential to Strata. Before each bypass the gateway checks the upstream health response reports that API-key protection is enabled and that an unauthenticated `/v1/models` request is rejected. If these checks fail, it returns 503. Strata still validates every actual key. Health endpoints remain public as in the existing service. Consequently, a person who retains a valid Strata API key can continue calling its API even after an invitation is revoked; revoke their API key separately.

The prototype rejects encoded paths, disallows methods other than GET/HEAD/POST, and strips cookies and forwarded-identity headers before proxying to Strata. These choices may not support all clients or routes and need testing against the actual installed version. Cookie authentication on non-API POST requests also requires a matching Origin. The upstream must be plain HTTP on 127.0.0.1 and must not be exposed through a separate unprotected browser route. A user who can directly reach the existing Strata origin or a different tunnel can bypass the page gate. API-key access is intentionally separate.

`oauth2-proxy.example.cfg` is only a reviewable sketch. Replace all example names and private file paths; use a dedicated restricted OIDC client, a 32-byte random cookie secret file, PKCE S256, nonce validation, HTTPS, and a trusted local proxy chain. The identity provider must be configured to restrict that client to the verified owner and invitees *before* exposing the proxy. `skip_auth_strip_headers=false` preserves the user's existing Authorization header; its safety depends on this gateway's independent, client-bound introspection on every protected request, and on not exposing the gateway directly. Do not blindly copy it into a live system.

For the gateway process set `AUTH_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET_FILE`, `STRATA_PUBLIC_ORIGIN`, `STRATA_UPSTREAM`, and optionally `GATEWAY_PORT`, then run `node gateway/server.mjs`. It binds only to loopback. The separate oauth2-proxy binary is not bundled.

Before any cutover: test real signed-in browser behavior, expired and revoked tokens, primary and secondary Strata keys, streaming and cancellation, API clients, direct-origin bypasses, proxy trust boundaries, recovery from identity-provider outage, and a full stop/restore of the old tunnel route. Use a separate preview hostname first. Independent security review remains outstanding.
